Qwen / Kimi / DeepSeek / GLM 开源动态日报

信息来源

DeepSeek 官方更新日志与 Hugging Face 组织页，Kimi K3、Qwen、GLM-5.2 官方模型页及 GitHub / ModelScope 组织页，Artificial Analysis 独立评测，Hugging Face 社区技术文章。微信公众号文章仅作为线索，核心结论以 DeepSeek 官方日志为准。完整取证底账见第 6 段。

DeepSeek 正式版 API 上线了，但新权重还不能下载。

用户现在可以通过官方接口调用 DeepSeek-V4-Flash 正式版。官方公布的 Terminal-Bench 2.1 成绩是 82.7，但 7 月 31 日更新后的模型权重还没有开放，用来测试的 Harness 工具也没有公开。因此，外部开发者目前无法在自己的服务器上部署同一版本，也无法独立复测 82.7。简单说：API 已上线，新权重还没有开放。

  • 01

    Kimi

    已开源

    社区把 K3 的 1-bit 量化版从 1.56TB 压到 594GB，讨论由“权重能否下载”进入“本地设备究竟能跑多快”。594GB 仍远超 128GB 内存，必须依赖固态硬盘卸载；如果没有吞吐量、首 token 延迟和长上下文稳定性的实测，“Mac Studio 可运行”仍只是能启动，不代表能用于生产。

  • 02

    Qwen

    已承诺

    Qwen3.8 仍只有“soon”的开放权重承诺。Hugging Face、ModelScope、论文页和 GitHub 均未发现权重、模型卡或许可证。它是短期内最可能改变开放权重榜单的变量之一，但现在连参赛资格都没有，后续先看实际文件，不看预告措辞。

  • 03

    DeepSeek / GLM

    已有开放权重0731 未验证

    DeepSeek 今天更新的是 Flash 正式版 API，已有 Preview 权重继续采用 MIT，不能把 API 升级写成 0731 权重开源。Hugging Face 社区文章称其团队曾自托管 GLM-5.2 处理自主智能体攻击取证：商业 API 会拦截恶意命令和攻击载荷，自托管则让数据留在内部。模型未必总榜第一，也可能凭部署成熟度进入高敏感业务。

  • 04

    榜单为什么变

    Kimi K3 当前以 57 分排总榜第 4，比 07-17 入榜时低一位。直接原因是后来加入的 Claude Opus 5 以 61 分排到前面，Kimi 自身分数没有下降。GLM-5.2 从开放权重榜首退到 Kimi 之后也是同理：GLM 仍是 51 分，只是 Kimi 以 57 分超过了它。这两次变化都是竞争对手改变，不是原模型重新测差了。

  • 05

    为什么不同榜单名次不一样

    总榜、Coding Index 和 Agentic Index 使用不同题目与权重；Artificial Analysis v4.1 还替换了测试集，并把智能体任务权重提高到 34%。Harness、推理档位和 API 版本同样会改变结果。看排名至少要同时记录分数、榜单范围、版本、日期和 Harness，单独截一张名次图很容易误读。

  • 06

    接下来可能重排什么

    DeepSeek 若补发 0731 权重和 Harness，第三方才能判断 82.7 能否复现，并确认正式版后训练是否足以改变开放权重模型的编码、智能体排名；Qwen3.8 若真正给出权重、模型卡和许可证，也会直接进入同一比较。在这些文件出现前，两者都不能先写成“已经开源”。

  • 07

    下一轮竞争看什么

    总榜未必最先给出答案。短期更值得盯四件事：DeepSeek 是否从 API 走到可复现权重，Qwen 是否兑现开放承诺，Kimi 594GB 量化能否交出可信速度，以及 GLM 的自托管取证案例是否出现更多可复核部署。下一轮差距可能先出现在复现成本和部署可用性上。

  • 08

    开放权重争论升到政策层

    围绕 Kimi K3 的“蒸馏指控”，中美交锋已不只是企业之间的口水战。路透社经 Yahoo 转载的报道称，中国商务部 07-27 正式指责美方搞“AI 霸权主义”，并表示将采取必要措施维护中方权益。美国科技公司内部也不是一个声音：Anthropic 没有签署英伟达、微软、Meta、Hugging Face、谷歌、OpenAI 等 50 家机构支持开放权重的联名信。需要说清楚的是，Anthropic 同时表示不支持全面禁止开放权重模型；它拒签，是因为不认同联名信关于开放访问更有利于防御方的判断，并主张加强芯片管制、打击工业级蒸馏和强制安全评估。接下来影响模型能否使用的，可能不只有许可证，还包括出口管制、安全评估和针对单个模型的审查。

2Kimi（K3）已开源

今天没有新的 K3 权重版本，重点是开放权重后的实际采用和成本边界已经更清楚。

  • 开放状态与规模：官方仓库已有 safetensors 权重和 Kimi K3 License。模型是混合专家架构，共 2.8 万亿参数，每个 token 激活 1,040 亿参数，支持文本、图像和 100 万 token 上下文。T1Kimi K3 官方模型页
  • 性能：官方给出 GPQA Diamond 93.5、DeepSWE 67.5、Terminal-Bench 2.1 为 88.3；Artificial Analysis 独立综合指数为 57，在当前开放权重对比组中最高。两套测试口径不同，不能把单项分数直接互证。T1官方模型卡　T3Artificial Analysis
  • 速度与价格：Artificial Analysis 实测 Kimi 官方 API 输出 34.7 tokens/s，价格为每百万 token 输入 3 美元、输出 15 美元。持续生成和大批量调用时，速度与成本会成为约束。T3Artificial Analysis Kimi K3 页面
  • 能否自建：官方全量模型仍面向多卡服务器。Unsloth 的 1-bit 量化把体积从 1.56TB 压到 594GB，并称准确率保留约 78.9%；594GB 无法直接装入 128GB 内存，若依赖固态硬盘卸载，实际速度仍未验证。T3Unsloth 量化帖子及第三方复核
  • 社区采用：仓库当前约 38.8 万月下载、9,110 个点赞，已有 22 个微调、25 个量化和 14 个 Spaces。自建者仍主要是有多卡或高端本地设备的团队。T1Hugging Face 模型页
  • 许可证算盘：连续 12 个月总营收超过 2,000 万美元的模型即服务业务需要另签协议；月活超过 1 亿或月收入超过 2,000 万美元的产品需要显著展示“Kimi K3”。中小团队和内部使用基本放行，重点约束大规模 API 转售与超大型商业产品。T1Kimi K3 LICENSE 原文
  • 官方风险点：多轮对话和工具调用必须完整回传上一轮的 reasoning_content 与 tool_calls，会增加上下文成本，也要求使用方谨慎处理推理历史中的敏感信息。T1Kimi K3 官方模型卡
  • 公开落地：模型页列出 Together AI、Fireworks、Featherless AI 等托管服务，但本次未验证到独立企业客户案例。推理服务上架不等于终端客户正式投产。T1Hugging Face 模型页

4DeepSeek / GLM

4.1 DeepSeek（V4-Flash）　已有开放权重 0731 权重未验证

今天的变化是正式版 API 公测，不是新的开放权重发布。

  • API 正式版：调用名仍为 deepseek-v4-flash；正式版原生支持 Responses API，并针对 Codex 做了适配。DeepSeek-V4-Flash-0731 与 Preview 的架构和规模一致，只重新进行了后训练。T1DeepSeek 官方更新日志
  • 官方跑分：Terminal-Bench 2.1 为 82.7、DeepSWE 54.4、Toolathlon Verified 70.3、NL2Repo 54.2，后训练重点转向代码智能体和工具调用。T1DeepSeek 官方更新日志
  • 测试口径限制：公开代码智能体跑分使用尚未发布的 DeepSeek Harness minimal mode，参数为 max effort、top_p=0.95、temperature=1.0；DSBench-FullStack 与 DSBench-Hard 是内部测试集。目前属于官方自评，尚不能视为第三方复现。T1DeepSeek 官方更新日志
  • 权重状态：Hugging Face 仍只有原 DeepSeek-V4-Flash 仓库，模型卡仍称 Preview。仓库采用 MIT，公开 safetensors；模型为 2,840 亿总参数、130 亿激活参数、100 万 token 上下文。未发现名为 DeepSeek-V4-Flash-0731 的仓库。T1DeepSeek 模型页与组织页
  • 已有生态：原 Flash 仓库约 300 万月下载、1,900 个点赞、116 个量化版本和 100 个 Spaces。这说明 Preview 权重已有采用基础，但不能证明 0731 后训练权重已经开放。T1DeepSeek-V4-Flash 模型页
  • 更新范围：本次只升级 Flash API，DeepSeek-V4-Pro API、应用和网页端均未变化；V4-Pro 正式版仍只写“soon”，应标为已承诺。T1DeepSeek 官方更新日志

4.2 GLM（GLM-5.2）　已开源

GLM-5.2 不是今天新发布，但它已有公开的高敏感场景自托管案例。

  • 开放状态与规模：官方提供 7,530 亿参数 safetensors，混合专家架构每个 token 激活约 400 亿参数，支持 100 万 token 上下文，只处理文本；仓库采用 MIT，官方明确称无地区限制。T1GLM-5.2 官方模型页
  • 官方性能：模型卡给出 SWE-bench Pro 62.1、GPQA Diamond 91.2、Terminal-Bench 2.1 为 81.0（Terminus-2）或 82.7（最佳公开 Harness）。不同 Harness 会显著影响智能体跑分，引用时必须连同测试框架一起写。T1GLM-5.2 官方模型卡
  • 独立评测：Artificial Analysis 综合指数为 51，低于 Kimi K3 的 57；输出速度为 115.8 tokens/s，约为 Kimi 的 3.3 倍。GLM-5.2 的长处更偏向服务速度和部署成熟度。T3Artificial Analysis
  • 价格与可用性：API 中位价格为每百万 token 输入 1.40 美元、输出 4.40 美元、缓存命中 0.26 美元，低于 Kimi K3，但在同规模开放权重模型中仍属偏贵。T3Artificial Analysis GLM-5.2 页面
  • 部署生态：官方模型卡列出 SGLang、vLLM、Transformers、KTransformers、Unsloth 和昇腾方案；Hugging Face 另显示 126 个量化版本、100 个 Spaces。T1GLM-5.2 模型页
  • 真实落地：Hugging Face 社区文章称，其团队在处理 07-16 披露的自主智能体攻击时，将 GLM-5.2 部署在自有基础设施上分析恶意命令与凭据，因为商业 API 的安全护栏阻断了取证请求。这说明开放权重对数据不出域和避免误拦截确有用途。T3Hugging Face 社区技术文章，2026-07-20
  • 今日增量判断：Z.ai 组织页没有 07-31 新模型，GLM-5.2 权重显示 29 天前更新。今天活跃的是 Synapse 和 SDK，属于工具链更新，不能写成 GLM 新权重发布。T1Hugging Face 与 GitHub Z.ai 组织页

4.3 榜单怎么看：总榜、细分榜为什么会变

名次变化不等于模型退步。 Kimi K3 在 07-17 以 57 分进入总榜时排第 3；Claude Opus 5 后来以 61 分进入榜单，Kimi 分数没变，当前顺延到第 4。GLM-5.2 曾以 51 分领跑开放权重模型，后来被 57 分的 Kimi 超过，模型本身也没有因此变弱。
